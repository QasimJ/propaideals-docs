## What Claude can do once connected

| Ask | Claude uses |
|---|---|
| "Find 2-bed flats under £250k in M1" | `search_properties` |
| "What's that worth, and what would it rent for?" | `value_property` |
| "Show me the comparable sales backing that" | `get_comparables` |
| "How is the M1 market performing?" | `get_area_market` |
| "Is this a good deal?" | `score_deal` |
| "What has it sold for before, and which strategies does it fit?" | `get_property_details` |
| "Give me everything on this property" | `get_property_report` |

The comparables are the part worth knowing about: every comparable carries a
confidence tier (gold, silver or bronze), and sales that were repossessions,
right-to-buy, auctions or family transfers are flagged as **non-standard**, as
are likely **flips**. Claude is told to treat those with caution when
averaging, so a headline "£/sqft" is not quietly skewed by a repossession
three doors down.

## Connect from Claude Desktop

Claude Desktop shares connectors with your claude.ai account. Add the
connector once — **Settings → Connectors → Add custom connector →
`https://api.propaideals.co.uk/mcp`** — either in the desktop app or on the
web, authorise as above, and it is available in both.

## Connect from Claude Code

Add the server from your terminal:

```bash
claude mcp add --transport http paid-property https://api.propaideals.co.uk/mcp
```

Then, inside a Claude Code session, run `/mcp` and pick **paid-property** to
complete the OAuth sign-in in your browser. Once authorised, ask things like:

```
> Value 12 Example Road, M1 4BT and sanity-check it against the comparables
> Pull the deal score for the property at <uuid> and summarise the risks
```

To remove it later: `claude mcp remove paid-property`.

## The OAuth consent flow

Authorisation is standard OAuth 2.1 with PKCE, run by Clerk on our behalf:

1. Your MCP client discovers the authorisation server from the
   protected-resource metadata at
   `https://api.propaideals.co.uk/.well-known/oauth-protected-resource`.
2. It registers itself automatically (RFC 7591 dynamic client registration) —
   no client id to copy anywhere.
3. You sign in with your normal PAID account and approve the consent screen.
4. The client receives an access token whose **audience is the MCP server
   only**. We validate signature, expiry and audience on every request;
   dashboard session tokens are rejected here, and MCP tokens are rejected at
   the dashboard.

Removing the connector in Claude (or in Claude Code, `claude mcp remove`)
stops further access; tokens are short-lived and expire on their own.

## Troubleshooting

**The connector shows zero tools.** This is protocol-version negotiation, not
an auth problem: a server and client that fail to agree a protocol revision
produce an empty tool list. Our server speaks every revision from `2025-06-18`
through `2026-07-28`, so first remove and re-add the connector (stale sessions
pin an old negotiation), and update your Claude client if it is very old. If
it persists, email us with the approximate time — we log the version each
handshake requested.

**`401` on every call after connecting.** Almost always an **audience
mismatch** — the token was minted for a different resource than the server
expects. Check the connector URL is exactly
`https://api.propaideals.co.uk/mcp` (no trailing slash, no `www.`), then
remove and re-add the connector so a fresh token is issued for the right
audience. Rejected audiences are logged on our side with the exact value the
token presented, so support can resolve a stubborn case quickly.

**Tools stop mid-conversation with a quota message.** You have used the
month's credits. Check usage at
[/dashboard/api](https://propaideals.co.uk/dashboard/api); upgrade or wait for
the month to roll over. Nothing is broken — the server refuses cleanly rather
than failing silently.

**A property tool returns "not found".** `score_deal`,
`get_property_details` and `get_property_report` key on a property UUID that
comes from `search_properties` (the postcode-keyed tools — search, valuation,
comparables, area market — don't need one). Ask Claude to search first; ids
from outside the platform (portal URLs, other APIs) will not resolve.

## Notes for developers

- **Transport:** Streamable HTTP at `POST /mcp`. Protocol revisions
  `2025-06-18` through `2026-07-28` are all served, so the endpoint works with
  older and newer clients alike.
- **Authorisation:** OAuth 2.1. The server publishes
  [RFC 9728](https://datatracker.ietf.org/doc/html/rfc9728) protected-resource
  metadata at `/.well-known/oauth-protected-resource`; tokens are validated
  for signature, expiry and audience.
- **No AI proxying.** The MCP server exposes data tools only. Claude does the
  reasoning; we do not bill you for a second model behind the scenes.
- **One quota.** MCP calls and REST API calls draw from the same monthly
  allowance on your account, so there is nothing to reconcile between them.
- **Costs are the REST costs.** Each tool's credit price is the sum of the
  [per-endpoint request costs](./rate-limits#request-cost-by-endpoint) of the
  endpoints it wraps — a single cost table governs both surfaces.
